# Health check

The health check of the container will verify if the WARP client inside the container is working properly. Specifically, 10 seconds after starting, a check will be performed every 15 seconds. If the inspection fails for 3 consecutive times, the container will be marked as unhealthy.

Note that Docker restart policies act on container **exit**, not on health status, so an unhealthy container is not restarted by Docker by itself. Recovery comes from the entrypoint supervisor: if the `warp-svc` daemon or the `gost` proxy dies, or if the WARP egress check (`healthcheck/connected-to-warp.sh`) fails `EGRESS_FAIL_THRESHOLD` consecutive times (default `8`, roughly 35-70 seconds of consecutive failures at the default `EGRESS_CHECK_INTERVAL=5` after the initial `EGRESS_GRACE_PERIOD=15` startup grace period; set `EGRESS_FAIL_THRESHOLD=0` to disable the watchdog), the supervisor exits the container and the restart policy brings it back up. You can also override `WARP_TRACE_URL` (default `https://cloudflare.com/cdn-cgi/trace`) if you want the trace check to hit an IP directly such as `https://1.1.1.1/cdn-cgi/trace`. Registration is persisted in the data volume, so the restart does not need to re-register; warp-svc also reconnects on its own after a restart, while a deliberate `warp-cli disconnect` is preserved. Note that with the watchdog enabled, a deliberately disconnected container will be restarted repeatedly (the persisted disconnect survives every restart and the egress check keeps failing); set `EGRESS_FAIL_THRESHOLD=0` for the duration of any debugging that needs WARP to stay down.

By default, the health check verifies live WARP egress by querying `WARP_TRACE_URL` (`cdn-cgi/trace`) for `warp=on` or `warp=plus`. Sometimes you may face a [host connectivity issue](host-connectivity.md), which is not covered by the default health check. If `BETA_FIX_HOST_CONNECTIVITY=1` is passed, host connectivity check will be added to the health check. If the check fails, the container will automatically fix it. This may prevent you from accessing certain intranet services of your organization, as the docker network subnet may conflict with the addresses of these services. This is a beta feature and may not work in all cases. If you encounter any issues, please report them.

If you don't want the container to restart automatically, you can remove `restart: always` from the `docker-compose.yml`. You can also modify the parameters of the health check through the `docker-compose.yml`.
